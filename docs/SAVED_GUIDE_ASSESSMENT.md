# 保存的巫妖攻略补齐了什么

结论：**这份网页比毕业配装JSON更全面。与已有JSON合用，已足够定义巫妖的核心收集、替代暗金和机制所需神像；它仍不是完整的开荒路线，也没有同时补齐死灵攻略。**

本次读取用户保存到Downloads的HTML及相关本地文件，没有执行网页脚本或重新请求Maxroll。标题、H1、canonical和正文都确认是 [Flay Mana Lich攻略](https://maxroll.gg/last-epoch/build-guides/flay-mana-lich-guide)，作者Volca。页面声明以80级角色为前提。结构化元数据的修改日期是2026-09-26，Changelog写2026-09-27更新Season 5；两种日期原样保留。

[资料摘录与来源记录](../sources/builds/flay-mana-lich-guide.json)保存原HTML哈希、标题、关键规则、ID和矛盾。HTML为456,595字节，配套目录有162个文件、约22.4MB，主要包含图片、样式、应用脚本与广告资源；文件数量不等于配装数量。原网页留在本地，仓库提交整理后的事实，不上传完整网页或整套资源。

## 已解决的实际缺口

| 原来仅凭JSON无法判断 | 网页补充的结论 | 对后续filter的影响 |
|---|---|---|
| BD启动门槛 | 600+魔力；需要Executioner's Tithe、Grasp of the Blood Mage和Traitor's Tongue | 明确核心装备；600是角色总魔力要求，不能写成单件装备条件 |
| 为什么堆魔力 | Deadly Plot与Chaos Rip将魔力用于伤害成长；Executioner's Tithe还支持Harvest回蓝 | 解释魔力素材的价值，而非只因毕业JSON出现T7就收集 |
| 点燃神像是不是随便搭的 | 点燃用于触发Exult in Misery | 原JSON中876有明确机制用途，不能随意删除或当通用输出词缀 |
| 虚弱从哪里来 | 优先由1×1神像腐化1069提供；没有时，1×2神像改用891 | 需要另一种神像配对方案，不能只收毕业843+854／876+886组合 |
| 暗金没刷到怎么办 | 项链和戒指有明确替代品；手套有后续升级 | 补收6种JSON未列出的暗金，详见下表 |
| 腐化属性怎么选 | Exulis优先智力转疯狂；避免力量转蛮力；有狂热来源时可用活力转猖獗 | 记录实际取舍；不能把随机传奇词缀的好坏当唯一价值判断 |
| 换手套是否改变需求 | 换Immortal Vise后，攻略计算的暴击率从111.8%变为94.6% | 升级有补暴击需求，不能只改暗金名单 |
| 是否缺一份Starter导出 | 攻略明确没有Starter Planner；页面有Endgame和Aspirational标签 | 不再继续寻找作者没有提供的Starter；低等级仍依赖其他练级攻略和基底兜底 |

这些是攻略提供的事实与其收集含义。600+魔力并不等于满足全部成型条件；攻略同时强调Endgame各件装备的重要性。暴击数字是攻略配装计算，不能当作任何玩家当前角色的实测结果。

## 神像、祭坛与腐化依赖

1. 魔力主力神像：已有JSON的843“魔力与提高魔力回复”＋854“生命与魔力”，受Reliquary Nest433增强。保留组合，不把所有神像词缀混成任意两条。
2. 点燃：一枚Stout Weaver Idol，物品类型28，带876“点燃几率与点燃火焰抗性穿透”，用于Exult in Misery。原JSON还有886；正文确认876的用途，没有给出886不可替代的依据。
3. 虚弱：Minor Weaver Idol，物品类型26，腐化1069“击中时施加虚弱几率”。若没有这一来源，攻略建议Stout Weaver Idol使用891“提高持续伤害与击中时施加虚弱几率”。这意味着调整点燃神像的另一条词缀，并非在普通词缀池中无条件加入1069。
4. 暴击避免：Grand Survival of Might祝福与装备词缀97；不足时可补1×1神像腐化1067。祝福与角色面板属于玩家配置，不是掉落filter可以自动完成的事项。
5. 祭坛：Spire Altar（41:3）提供魔力；Carcinised Altar（41:4）是护甲选项。需要腐化词缀1105“魔力自装备的每个腐化神像”，并腐化所有装备的神像。不能只因为原JSON是41:3就排除正文推荐的41:4。
6. Exulis469：优先1084“智力转化为疯狂”；攻略要求避免1083“力量转化为蛮力”，因为会损失大量护甲；有狂热来源时1087“活力转化为猖獗”是良好次选。攻略明确它预腐化掉落，带两条属性转换和一条随机传奇属性，即使传奇属性不理想也有价值。
7. 升级Immortal Vise时，攻略推荐用腐化1075“增加暴击加成与每点敏捷提高暴击几率”补剩余暴击需求。是否足够取决于玩家实际配装，不能按目标JSON固定结论。

以上普通词缀、腐化词缀和角色总属性必须分开处理。这里没有声称XML能筛掉所有不合适的腐化成品；实际条件表达与覆盖关系在生成时核对，客户端能力另行验证。

## 保存文件中的矛盾与缺失

**Planner链接矛盾。** 标题和正文是巫妖，保存DOM也有Flay技能及26／22／24／24／26的技能点数；但装备、技能、被动和Loot Filter嵌入的data-le-profile均写`2ai4s0qh`、data-le-id为`1`，三个“Open in Planner”链接指向用户此前提供的死灵Planner。用户给出的巫妖地址是`y21h9h0x#2`，它没有出现在HTML中。成因未确认。继续以已有巫妖JSON作为配装数据，以本文正文作为机制资料；不能按这个嵌入链接把死灵配置或过滤器归给巫妖。

**FAQ数量矛盾。** FAQ最低装备文字多出“two Traitor's Tongue”；开头相同要求没有“two”，装备说明明确匕首在副手，已有JSON是主手Executioner's Tithe＋一把副手Traitor's Tongue。保留矛盾记录，不据此虚构双匕首需求。

**未选择的标签不等于已保存完整配置。** 保存时Endgame按钮为active，Aspirational未选，Stat Priority未选。本地没有识别出可直接复用的两阶段原始Planner JSON。现有用户JSON与正文对应，但不能仅凭URL的`#2`断言它是哪一个阶段。

**Loot Filter只有入口。** HTML中存在按钮，没有ItemFilter XML内容，相关入口还带上面的Planner矛盾。因此本次没有取得可直接拿来对照的Maxroll成品filter。配套应用脚本不能代替具体配装数据。

仍缺每部位可接受的最低词缀阶数、最低LP／WW、完整练级路线和Skeleton Necromancer正文。玩家库存、进度、阵营与收紧偏好也不在网页内。这些不妨碍做终局收集初版，但会影响严格程度，不能用毕业roll=1替代判断。

本次完成保存资料核对与规则补充，未生成个人filter。巫妖已经有“配装JSON＋机制／替代说明”；另一份死灵攻略若按同样方式提供保存HTML，可以继续补齐死灵的缺口，无需重交已有JSON。

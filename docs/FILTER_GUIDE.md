# Raxx S5 过滤器中文说明

这是一套以 Circle of Fortune（命运之环，CoF）／自给装备为主要场景、覆盖开荒到终局的通用收集模板。它按照“传奇与稀有物品保留、好词缀和制作素材、神像、升级过渡装备”的层次决定地上物品是否显示，以及用什么提示显示。它不会判断一件装备是否真的比身上装备更好，也没有记录你的库存。

下文的“第N条”统一指 `Order+1`。全部条目可在 [完整索引](RULE_INDEX.md) 查询；原始字段和选择列表在 [rules.json](../analysis/rules.json)。英文名字里的说明不等于实际筛选条件。

## 1. 先理解匹配顺序

游戏从列表顶端向下检查启用的规则；较上方的规则优先。因此一件装备的最终提示取决于最先匹配的规则，后面的颜色、声音或隐藏要求不会再叠加上去。[官方说明](https://support.lastepoch.com/hc/en-us/articles/46361669143067-Loot-Filter)

在本文件里，越小的 `Order` 越靠上；第8条保留传奇，第163条无条件隐藏兜底。XML 本身却把第163条写在最前面，再一路写到第1条。未来读取或编辑时，不能把 XML 的第一条当作游戏最高优先级。

一个规则内的多个条件共同满足。例如第62条同时要求满足两个词缀条件、选中的物品类型和“未腐化”。不同 SHOW 规则提供多条保留路径；较早的 HIDE 会截断后面的保留路径。

文件的56条蓝色关闭条目是使用说明，按“由底部向上找蓝色说明，再配置它下面的规则”来阅读。它们仍是普通规则对象，不是引擎专用注释；应保持关闭，不能一键启用全部规则。

## 2. 几个必要术语

| 术语 | 在这里的意思 |
|---|---|
| BD / Build | 一套技能、装备与词缀需求 |
| BIS | 最适合该用途的选择；写在名字里不会让游戏自动知道你的 BIS |
| Base / Subtype | 底材，比如某一种匕首；不同底材有不同固有属性 |
| Affix / T | 词缀及其阶数；筛选一条好词缀不等于整件装备全词缀完美 |
| Exalted | 崇高装备；本模板常用 T6/T7 词缀筛选它们 |
| LP | Legendary Potential，传奇潜能 |
| WW | Weaver's Will，织者意志 |
| Slam | 把崇高装备的词缀用于传奇制作；底材要求与直接穿戴用途不同 |
| Shatter | 拆解来积累词缀碎片；规则只是提示，不会自动拆解 |
| Ascend | 用 Rune of Ascendance 尝试获得暗金／套装的制作用途 |
| Havoc | 用 Rune of Havoc 调换词缀阶数的制作用途；被显示不代表制作必定成功 |

## 3. 顶层保护：第8–24条

**第8条：所有传奇。** 只有 `LEGENDARY` 稀有度条件。没有职业、等级、词缀、底材限制；默认保留物品原色。

**第12条：高潜能暗金。** `UNIQUE` 加上 LP≥3 或 WW≥20，没有暗金名字白名单。它使用橙色、强调、声音6和最大光柱；并不是后面 BIS 崇高使用的金黄提示。

**第13、14条：中低潜能暗金。** 门槛分别为 LP≥2 或 WW≥17、LP≥1 或 WW≥14，但两条都带412项的明确物品清单，且清单相同。“all Uniques”不能解释成任意新旧暗金都显示。当前高于门槛但不在清单的物品，需要由第12、15、73条等其他路径保留。

**第15条：指定稀有或 BD 需要的暗金。** 选143项。名字写着 LP0，实际没有潜能条件；它保留的是所选名字在任意 LP 下的物品。名单也并非游戏自动识别的“最稀有”集合。

**第16条：指定套装。** 选21项，亮绿、强调、有声音。它没有另加 SET 稀有度条件，筛选依据是所选物品 ID。完整名单见 [暗金／套装清单](SELECTED_UNIQUES.md)。

暗金 roll 字段需要原样保留：第13、14、16条的已记录上下限为 nil；第15条还存在364个 `0–255` 的 roll 范围，共728个非空边界。这里没有发现更窄的数值区间，但不能把这些字段一律改成 nil，或把255当作游戏面板属性值。

**第19–24条：材料与资源。** 分别显示所有雕文、钥匙／资源、共鸣、符文、碎片和编织回响。这六条在职业隐藏之前，构成重要保留路径。第20条的 `AllKeys` 是旧格式字段名；官方1.4已把对应条件扩展为 Resources，不能只按英文单词“Keys”理解。[1.4官方更新说明](https://forum.lastepoch.com/t/last-epoch-shattered-omens-patch-notes/80571)

## 4. 职业隐藏：第29条

当前它是 `HIDE`，默认关闭，职业字段为 `None`，尚未填写要排除的职业。上游明确在最新提交中将其关闭，原因是未配置时可能把全部物品隐藏。不要直接勾上空配置。

它的位置在传奇、暗金、套装和资源规则之后，在崇高装备和神像规则之前。因此，配置并启用后：已经被顶层规则保留的其他职业稀有物品仍能显示；剩余匹配排除职业的物品被隐藏。第73条的“80级前显示所有暗金”也受这条较早的隐藏规则影响。

这是“物品的职业需求”条件，不是判断物品是否对某 BD 有用。通用武器、首饰等没有某个排除职业需求的物品，仍要靠其他条件过滤。以后为多个 BD 收集时，要保留所有目标 BD 涉及的职业，不能仅按正在玩的角色删去其他职业。

## 5. 金黄 BIS 区：第37–48条

**第37条：所选词缀中至少一条 T>7。** 它有946项词缀选择，单条比较为 `MORE 7`，数量为1。规则名字“All Tier 8 Items”表达作者意图，XML 的准确条件仍是“已选列表中的任一词缀阶数大于7”。它没有另加 EXALTED 稀有度条件。

**第38–47条：各部位至少一条指定 T7+ 词缀。** 数量全部为1，合计阶数比较全部为 ANY。不是要求全部勾选词缀同时出现，也不是要求四条词缀完美。作者预填了部分通用好属性，但仍须按 BD 调整。

| 条目 | 当前预填词缀 | 必须知道的范围 |
|---|---|---|
| 38 武器 | 暴击伤害加成 | 物品类型和底材都为空，不能仅凭名字视为只筛武器 |
| 39 副手 | 增加生命、提高生命、复合生命、暴击伤害加成 | 物品类型和底材都为空 |
| 40 头盔 | 增加生命、提高生命 | 类型为头盔 |
| 41 衣服 | 增加生命、提高生命、护甲及降低暴击额外伤害 | 类型为身体护甲 |
| 42 腰带 | 三种生命、冷却恢复、护甲及降低暴击额外伤害、元素抗性、物理抗性 | 类型为腰带 |
| 43 鞋子 | 增加生命、复合生命、移动速度、冷却恢复 | 类型为鞋子 |
| 44 手套 | 增加生命、复合生命、暴击率 | 类型为手套 |
| 45 项链 | 增加生命、暴击伤害加成 | 类型为项链 |
| 46 戒指 | 增加生命 | 类型为戒指 |
| 47 遗物 | 增加生命、增加生命与生命再生、暴击伤害加成 | 仅底材3/4/5：Copper Chalice、Silver Grail、Golden Chalice |

第47条已经限制了三种底材。若目标是其他职业遗物或传奇制作素材，原样沿用这条可能遗漏候选。底材 ID 必须连同 `RELIC` 类型解释，不能把数字3当作通用底材名称。

同类武器若用途不同，应把“类型／底材”和“正确词缀”绑定在各自规则中。例如一个 BD 要匕首词缀A，另一个要法杖词缀B，把所有底材和所有词缀直接合并会额外保留“A在法杖上”这种不需要的组合。直接穿戴与传奇制作素材，也需要分别判断是否限制具体 subtype。

**第48条：双崇高。** 在选中的623项词缀里，至少两条 T≥6，范围覆盖23种装备类型。`combinedComparsionValue=14` 虽然保存在文件中，但比较模式为 ANY，因此没有“合计≥14”要求。T6+T6 就满足这个词缀条件，不必有 T7。文件没有 `AffixCountCondition` 或 sealed 限制，不能从名字保证两条都未封印。

## 6. 崇高与制作区：第60–75条

| 条目 | 条件与用途 |
|---|---|
| 60 T7武器／副手 | 15类武器／副手，42项词缀中至少一条 T≥7；不限制具体底材 |
| 61 T7其他装备 | 8类护甲／首饰／遗物，343项词缀中至少一条 T≥7；不限制具体底材 |
| 62 Havoc候选 | 491项中至少一条 T≥7；另一个10项列表至少命中一条；23类装备；未腐化 |
| 63 T6武器／副手 | 16项选择中至少一条 T≥6；角色0–84级；并非恰好T6 |
| 64 T6其他装备 | 338项选择中至少一条 T≥6；角色0–84级 |
| 68 崇高实验装备 | 有所选12项实验词缀之一，且物品稀有度为 EXALTED；默认启用 |
| 69 普通实验词缀 | 所选12项之一；默认关闭，没有EXALTED稀有度限制 |
| 70 冠军词缀 | 所选14项之一；默认关闭 |
| 73 暗金兜底 | UNIQUE，角色0–79级 |
| 74 崇高兜底 | EXALTED且命中所选668项词缀之一，角色0–59级 |
| 75 腐化兜底 | 已腐化且命中所选18项词缀之一，角色0–59级 |

第62条的第二个列表包括移动速度、冷却恢复、生命系列、暴击属性、范围、持续伤害等10项，全部也在第一个列表中。因此同一个 T7 词缀可能同时满足两个条件；文件并没有要求“两条不同词缀”。它也不限于武器／副手。是否能通过制作得到需要的结果，仍要检查装备本身和制作机制。

第60/61/63/64条用淡紫色，当前自定义声音为 None；第62条亮绿。视频口头把好装备概括为红色，但不能因此把当前 XML 的这些条目描述成红色。

第68条只要求“装备为崇高且有实验词缀”，没有明确要求“实验词缀本身为T6/T7”。第74、75条也不是纯稀有度／腐化标记的无条件显示：它们还有词缀列表。

## 7. 定向收集与碎片：第81–90条

**第81条：升华素材。** 允许 NORMAL/MAGIC/RARE/EXALTED，要求物品带 CoF 标记且未腐化；物品类型仍为空。这里的 CoF 是物品条件，不是“只要角色加入 CoF 就匹配”。如需 Merchant's Guild（商人公会，MG）场景，未来应按需求去掉或调整这个条件，而非只修改 filter 名字。

**第82条：找指定底材。** 允许四类普通至崇高装备，类型和底材都为空，当前启用。

**第83条：补紧缺碎片。** 词缀列表为空、数量1、advanced=false，当前启用。它没有稀有度、等级或物品类型限制。

官方1.4明确规定：空词缀选择匹配任意词缀。社区格式实现把空物品类型视为无类型限制。因此第81/82/83条必须视为需要审查的宽泛规则，不能假设“未填写所以不生效”。按空类型广泛匹配的解释，第82条会先保留普通至崇高装备，从而覆盖下方碎片规则的橙色提示；第81条还会优先把符合它条件的物品标绿。实际客户端应按 [验证清单](BEHAVIOR_CASES.md) 检查这一点。

**第84–88条：各职业碎片。** 选中的职业词缀至少一条 T≥4，稀有度限 MAGIC/RARE/EXALTED。五个职业都默认启用，并没有“已选其他职业规则自动关掉”的动态逻辑。

**第89、90条：进攻／防御碎片。** 所选词缀至少一条 T≥5，稀有度同上。全部碎片条目只是拾取理由；若装备同时满足更高的 BIS 条件，会先显示 BIS 提示，不会再变橙。

库存充足以后，是否关闭这些碎片收集规则需要人为决定。本阶段不修改其状态。

## 8. 神像与祭坛：第99–129条

第99/100/101条对应全职业通用的1×1、1×2、2×1神像。第102–126条按五职业分别提供2×2、1×3、3×1、1×4、4×1的五条规则。所有这些条目都默认启用，词缀列表都为空，要求数量2，advanced=false。

作者的配置意图是填写该 BD 的理想词缀，要求一件神像同时有两条需要的词缀；早期可放宽为1条。在尚未填写的原始文件里，空列表会扩大匹配范围；“空列表 + 数量2”到底如何在客户端计数，是需要实际验证的边界，不能从词缀为空推导“不显示”。它们的 subtype 已区分职业神像，但没有独立 ClassCondition。

若多个 BD 的前后缀需求不同，直接合并列表并设置“至少2条”会产生跨 BD 的组合。例如 BD A需要前缀A+后缀X，BD B需要前缀B+后缀Y；合并后可能把A+Y也当作合格。后续需要按组合保留规则，不能仅做词缀集合的并集。

**第127条：神像祭坛。** `IDOL_ALTAR` 类型，13种已选底材，20项词缀中至少1条。默认有薄荷绿、大光柱与声音。它有实际预填列表，仍须对照目标 BD 审查。

**第128、129条：过渡神像。** 共用143项选择，第128条要求至少2条，角色0–89级；第129条至少1条，角色0–74级。它们的名称“Godly/Decent”不表示检查了词缀数值区间；当前没有按roll百分位筛选。

## 9. 开荒区：第134–162条

| 条目 | 作用与退出等级 |
|---|---|
| 134 | 显示 UNIQUE/SET/LEGENDARY/EXALTED，角色0–59级 |
| 135 | 普通尺寸神像、命中所选438项词缀，角色0–59级；保存了T3阈值但 advanced=false |
| 136/137 | 开荒BIS武器／副手，角色0–59级；当前类型和底材为空，须填需求 |
| 138–145 | 各部位预选开荒底材，角色0–59级；没有额外词缀优劣条件 |
| 146–148 | 所选物理抗性／生命、移动速度／CDR、其他抗性至少一条T≥3，角色0–49级 |
| 149–151 | 对应早期属性至少一条T≥2，角色0–29级 |
| 152–154 | 弓、近战方向、施法方向的所选类型与词缀，角色0–29级；实际类型列表以索引为准 |
| 155 | 所有RARE，角色0–29级 |
| 156–161 | 指定早期遗物／副手底材、Silver Ring、Ruby Amulet，角色0–11级 |
| 162 | 广泛显示所选32类装备／普通神像，角色0–9级；不等于含祭坛在内每一种物品 |

“Turns off at 60”是 `maximumLvl=59` 的角色等级条件，并不是脚本到60级自动把勾选框关闭。回到低等级角色，同一条规则可能重新适用。30、50、60、75、80、85、90等临界点均按相同方式理解，不能误作地图等级或物品需求等级。

这一层提供兜底，不保证最终显示来自这一层。未配置的较上方宽泛规则，可能让这些等级条件在最终效果上不再明显。

## 10. 颜色与声音怎样读

| 当前色号 | 近似颜色 | 主要用途 |
|---:|---|---|
| 12 | 蓝 | 关闭的说明条目 |
| 3 | 金黄 | T8、BIS T7、开荒BIS底材 |
| 4 | 橙黄 | 碎片收集 |
| 5 | 橙 | 高LP／WW暗金 |
| 7 | 红 | 早期武器和部分早期底材 |
| 8 | 粉 | 指定底材／紧缺词缀 |
| 11 | 淡紫 | 双崇高和一般T6/T7候选 |
| 15 | 薄荷绿 | 神像、祭坛 |
| 16 | 亮绿 | 指定套装、Havoc、升华素材 |

未开启 `recolor` 的规则保留物品原色；不能把其 `color=0` 解读成强制白色。`emphasized` 是独立字段，`BeamOverride=false` 时不能只读保存的光柱大小就断言有额外光柱。

基底只使用声音 ID1和6。社区格式映射中1是 None，6是 Begin；None表示这条不选择额外过滤器音效，不证明游戏完全没有任何固有掉落声。声音、地图图标、光柱颜色分别有自己的 ID 表，不能把同一个数字在不同字段里视为同一颜色／效果。地图图标目前按原始 ID 保留，未主观命名；听感未验证。

颜色是命中规则的提示，不是多个用途标签的叠加。以后为同等优先级的多个 BD 收集，一件物品只能得到先匹配规则的整组提示；其“也适合其他 BD”的用途不能仅靠第二条规则再加一个声音。

## 11. 使用或定制前的配置检查

1. 先复制基底，为自己的需求创建另一份，保留原文和出处。
2. 明确所有要收集的 BD、职业、武器／副手与制作用途。
3. 审查第29条，先选要排除的职业，再决定启用；未确定的目标职业先保留。
4. 填写或有意关闭第38/39、81/82/83、136/137条的空配置；审查第47条遗物底材限制。
5. 为目标神像填写组合，审查第99–126条空词缀列表；是否由2条放宽为1条应明确决定。
6. 核对第13–16条暗金／套装白名单，并判断实验／冠军、碎片库存及CoF条件。
7. 在游戏打开filter编辑器，用地面标签的规则编号确认真正命中的条目。默认 SHIFT+F 打开，X可临时查看被隐藏物品。[官方操作说明](https://support.lastepoch.com/hc/en-us/articles/46361669143067-Loot-Filter)

本仓库完成了原文解析、来源核对和条件解释。空选择边界、封印词缀计数、游戏导入兼容性与具体提示效果的最后确认，见验证清单；它们没有被写成已完成的实测结论。

# 两份 Planner 数据的信息量与适用范围

结论：这两份数据足够定义**所示目标配装的收集规则**，但不足以独立还原攻略的**过渡装备、替代方案、成型门槛和收集优先级**。可以据此做终局目标试版；不能把它当作已经完整理解两篇BD攻略。

后续补充：用户已提供保存的Flay Mana Lich网页，其中600+魔力、核心装备、6种替代／升级暗金及神像依赖已核对，见 [保存网页评估](SAVED_GUIDE_ASSESSMENT.md)。巫妖这部分缺口已有答案；下文保留的是两份JSON本身的能力边界，死灵正文仍待补齐。

来源是用户提供的 [巫妖附件](../sources/builds/flay-mana-lich.json) 与 [死灵内联JSON](../sources/builds/skeleton-necromancer.json)。[来源记录](../sources/builds/manifest.json)保存用户给出的Planner地址、哈希和技能名映射。通过技能树与配装内容识别BD对应关系；导出本身没有BD名称或装备阶段标签。没有绕过Maxroll的访问限制读取网页。

合并后共有17种暗金、48种不同词缀ID。词缀统计包含装备、神像、祭坛以及腐化属性，不是48种普通装备词缀。重复的戒指、神像按实例保留，不误计成更多独立需求。

此外还有每件物品的类型／底材ID、词缀阶数和roll、暗金属性roll、固有属性roll、腐化标记，以及职业、专精、技能节点和加点顺序。两份weaverItems及weaver.history为空。神像数组里的null是空位置，不是额外神像；不从数组长度直接断言实际可用格数。

技能名可以用本地化数据解码：

- 巫妖：Flay、Reaper Form、Chaos Bolts、Marrow Shards、Harvest。
- 死灵：Rip Blood、Dread Shade、Summon Skeleton、Aura of Decay、Bone Curse。

被动和技能history可以用于还原所选加点记录与顺序，但没有配套的“这个阶段应换什么装备”说明。

## 已经能直接用于filter的内容

1. 建立目标暗金名单。两套都要酿酒大师的皮带扣416和山之麓253，可作为共同需求；其余分别保留。
2. 把目标词缀绑定到正确物品类型。巫妖用单手斧和匕首，offhand槽是匕首；死灵用双手斧，没有额外副手装备。
3. 收集所示成品对应的词缀素材。例如巫妖多个部位的T7魔力34、戒指T7智力502；死灵头盔／胸甲的T7共享流血406、武器T7召唤物持续伤害98、手套／项链T7召唤物范围与伤害945。
4. 保留神像的实际组合。例如巫妖17枚神像共享843+854的affixes组合，但腐化词缀有差异；死灵的862+319与862+870分别记录，不能把全部词缀混池后要求任意两条。
5. 单独表达实验与腐化需求。死灵鞋子记录了实验词缀679；腐化词缀保存在另一数组中，不并入普通可制作词缀池。
6. 保持两个BD同等收集优先级，并识别共同需求；提示颜色可区分，命中优先级仍需检查。

## 不能机械照抄的细节

**暗金本体与成品附加词缀需要分开。** 数据中所有常规装备都有uniqueID，又带目标affixes。这说明了目标成品上的属性，不能在暗金保留规则中要求“暗金掉落时已经带T7魔力”，否则会遗漏要收集的暗金本体。素材应另按物品类型和词缀保留。

也不能一律宣称这些词缀都来自同一种传奇制作步骤。社区数据库记录Exulis469可作为传奇掉落，并带预腐化与特定传奇词缀元数据；相关摘录在来源记录中。导出的最终样子不自动解释其获得步骤。

**暗金自己的subType不等于素材必须用同一底材。** 例如巫妖红戒指277的subType是3，不能据此只收这个底材上的T7智力素材；直接穿戴与制作用途应分开。

**神像不一定只有两条affixes记录。** 死灵的一枚大型神像在affixes中有941、287、897三条，此外还有腐化1071。不能把所有导出记录都压成固定“两条普通词缀”。这也不证明三条都应作为原始掉落的必选条件。

**tier与roll是示例目标，不是最低拾取门槛。** 两份记录的词缀roll、暗金roll、固有属性roll均为1。这符合统一设定理想目标的表现，但这是解释上的推断；数据没有给出允许低到什么程度。T7目标也不意味着T6一定应隐藏。

**写在配装里的词缀，不一定具有同等重要性。** 巫妖的1×2神像有876“点燃几率与点燃火焰抗性穿透”，但JSON没有解释它是核心、辅助还是示例搭配。不能仅因出现就断言两条词缀都必须同时命中。只有巫妖腰带的两条词缀带priority字段，其编码含义尚未核对，也不足以形成完整优先级。

## 仍缺的决策信息

| 缺少的信息 | 对filter的实际影响 |
|---|---|
| 过渡／低预算配装 | 暗金没有刷到之前，哪些普通或崇高装备可以穿，哪些武器类型仍有用 |
| 核心装备与替代品说明 | 哪些是必须尽早保留的成型装备，哪些只是终局优化，哪些替代装备也应显示 |
| 核心属性最低门槛 | 是否接受较低阶魔力、召唤物词缀等；目标roll不能代替启动BD的最低线 |
| 装备／技能之间的依赖 | 某装备或腐化效果不在时，哪些属性需求会变化 |
| 词缀的重要性与可替代性 | 每个部位哪些词缀必须有，哪些只要命中一项，哪些需要配对 |
| 神像／祭坛的获得与成长策略 | 收成品组合、未完成的制作胚子，还是更宽的替代组合 |
| 攻略版本与装备阶段 | 当前导出是否代表所给攻略的某个终局变体，是否漏了其他变体 |
| 玩家当前进度、阵营和库存 | 何时收紧、哪些碎片还缺、是否需要升华素材；目前只暂按基底CoF场景 |

原基底可以提供通用等级兜底、珍贵物品保护和制作素材框架，但其等级退出条件不等于这两个BD的具体成型路线。

## 下一步最有价值的补充

优先补两篇攻略里的**装备进阶／过渡装备、核心装备说明、关键属性门槛**段落，或者较早装备阶段的Planner导出。仅继续提供更多同一终局配置，帮助有限。无需重新提交这两份已有数据。

若先试用，可以做“这两份目标配装＋基底通用兜底”的保守版本，明确记录仍未覆盖的BD专属过渡与替代需求。完整覆盖的版本则应补齐上述决策后再收紧，而不是用毕业快照推测整条成长路线。

本次完成输入解析与完整性评估，未把它标成完整攻略研究，也未生成个人filter。

复现：`python -X utf8 scripts/analyze_build_inputs.py`。只读取仓库固定数据，检查全部引用ID并重建统计，不修改原始基底或两份Planner数据。

# 条件示例与验证边界

这些是原文条件的阅读案例，不是已运行的游戏掉落测试。每行说明指定规则自己的条件，整套filter仍取最早命中的启用规则。

| 案例 | 指定规则的结果或边界 | 理由 |
|---|---|---|
| T7暴击伤害加成，其他三条无用 | 可满足第38条词缀条件 | 数量1，T≥7；没有四条BIS要求 |
| 同一件物品有T6+T6，均在第48条所选列表 | 满足第48条词缀条件 | 至少两条T≥6；合计比较ANY，不要求14 |
| 只有T7的一条词缀 | 不满足第48条数量条件 | 数量需要2，单条阶数高不能替代数量 |
| 第48条所选词缀一条T6、一条T5 | 不满足其阶数/数量组合 | 达到T6门槛的词缀只有一条 |
| 角色84级、命中第63条所选T6词缀 | 第63条等级条件仍通过 | maximumLvl=84 |
| 相同物品，但角色85级 | 第63条等级条件不通过 | 不能据此断言整套filter隐藏，其他规则仍可能显示 |
| 角色79/80级的普通暗金 | 第73条在79通过、80不通过 | 角色范围0–79；其他暗金保留路径独立存在 |
| 被第15条选中的暗金，有LP1 | 第15条没有LP条件阻止它 | “at LP0”不是LP=0筛选 |
| LP2暗金，但名字不在第13条412项中 | 不满足第13条白名单条件 | 潜能达标不代替名字选择 |
| 增加生命25为T7，未腐化，类型属于第62条 | 同一词缀可以同时满足两个词缀条件 | ID25同时在491项T7列表和10项需求列表中 |
| 神像有A+Y；需求是A+X或B+Y | 合并列表且要求2可能误收 | 数量条件没有记录A/X、B/Y配对关系 |
| 第135条保存单词缀T≥3，但advanced=false | 不应报告已开启T3门槛 | 需保留开关与保存值的区别，客户端界面待核对 |
| 第29条开启但req=None | 存在广泛隐藏风险 | 上游明确因此改为默认关闭，不把None解释成安全空操作 |

## 首次进入游戏时要确认

优先检查以下实际问题，保存客户端版本和地面标签的命中规则编号。不要为测试改写原始基底；复制一份使用。

1. 导入后163条是否全部存在，次序是否与Order一致，格式版本9是否自动迁移，材料条件是否正常。
2. 第82条空类型与四种稀有度：一件不满足更高规则的普通/魔法/稀有装备是否被标粉。若是，证明它会覆盖下方的碎片和开荒提示。
3. 第83条空词缀：是否匹配任意普通装备词缀，以及是否会匹配暗金固有属性。官方确认空选择匹配任意词缀，未确认这里的所有边界。
4. 第99–126条空选择加数量2：一条或两条词缀的神像如何命中；腐化／封印词缀是否参与数量。
5. 第48条含封印T6/T7时是否算双崇高；基底没有排除sealed的条件，不能先假定不计数。
6. 第135条advanced=false时，T1/T2的所选神像词缀是否仍通过。
7. LP与WW各自达到第12–14条阈值时是否按“或”保留；0–255的Unique roll区间是否确实不收紧范围。
8. 声音1/6、地图图标和光柱的实际效果。尤其None仅表示过滤器音效选择，不能证明所有固有掉落声静音。
9. 配置第29条后，无职业限制装备、目标职业装备、排除职业装备、顶层珍贵物品和资源各自是否符合预期。

## 本阶段已经验证

- 两份原始来源的SHA-256；当前文件的Git blob SHA与上游一致。
- 163条连续Order与相反XML存储顺序；104条启用、59条关闭、56条蓝色说明。
- 全部15种条件进入索引；完整选择列表和原始nil/空字段被保留。
- 1,112个词缀均有名字映射；448个暗金/套装中445个可对上当前社区数据库，3个只可对上本地化；149个底材组合有映射。
- 七条版本差异；关键信息如第29条关闭、第135条advanced=false经过断言检查。

检查输出见 [validation.json](../analysis/validation.json)。这些检查证明资料解析与索引完整，不证明游戏执行或制作成功。

# 目标工作台使用说明

这个本地工具把导入filter中的BD目标填入我们审阅过的Raxx基底。可以保存多个BD，勾选本次需要收集的BD，指定主套路，预览后导出XML。

## 启动与保存

在仓库根目录双击 [start-tool.cmd](../start-tool.cmd)，浏览器会打开 <http://127.0.0.1:8765>。需要已安装Python 3及Windows的`py`启动器，无需安装Python第三方包或Node。关闭启动窗口或按Ctrl+C会停止服务。

也可以在仓库根目录运行：

```powershell
python -X utf8 tool/server.py --open
```

配置自动保存在当前浏览器中；使用右上角“保存配置”下载JSON备份，“载入配置”恢复。换浏览器或清除网站数据时，用JSON恢复。XML是游戏导入文件，JSON是可继续编辑的目标配置。

左侧“导入BD需求JSON”“保存本BD需求JSON”使用[共通需求格式](REQUIREMENTS_FORMAT.md)，保存正在编辑的一个BD、当前阶段的目标和可选来源：终局五类，练级两类。filter提取与攻略提取均可使用它。导入同id替换文件所指阶段的目标，保留另一个阶段、勾选状态和主副身份。真实样本是攻略835的[终局需求](../requirements/bleed-skeleton-roamer-guide-835.endgame.json)、[练级需求](../requirements/bleed-skeleton-roamer-guide-835.leveling.json)及[审阅表](BLEED_SKELETON_GUIDE_REVIEW.md)。

## 填写与导入

1. 用“新增BD”建立配置，或用“导入filter”选择XML／TXT、粘贴XML。导入结果是一个新BD，先核对提取数量和来源分类。
2. 标准Maxroll的目标规则自动识别；其他命名的filter可展开“核对来源规则与情报分类”，手动指定要提取的规则。通用词缀大池、隐藏规则、Strict的制作筛选不自动当作BD目标。
3. 终局五个入口的内容如下。列表支持中文、英文、ID搜索，多选时切换搜索不会丢失已选项目；可“只看已选”，也可显示旧／隐藏条目。练级切换后只显示词条与底材两份列表。

| 入口 | 填写内容与生成用途 |
|---|---|
| 所需暗金 | 选择目标暗金／套装ID。目标0LP也保留；声音沿用已确认的LP／WW分档。 |
| 装备词条 | 按部位填写目标池，可选限定底材。生成目标单T7、双T7含目标、双目标T7、非目标T7＋低阶目标；取消专门T6层。 |
| 祭坛词条 | 独立填写祭坛底材与目标池，至少一项目标、阶数不限，开始档。 |
| 神像词条 | 按类型、底材和普通目标池填写；至少一项开始、至少两项灵感。可以分别编辑候选层与两项层底材。 |
| 所需底材 | 指定底材＋同BD对应部位至少一条目标恰好T7，常驻。不会自动给其他装备T7素材加上这个底材限制。 |

没有来源的内容留空，不从另一来源补猜。比如骷髅Very Strict未提供定向底材，其底材栏为空；旧Strict有五组。脚部目标28／676／679全部保留；胸甲只有406，就不会添加192。攻略作为独立输入时可以记录它明确提供的目标，不能反写成Strict原本已有这些内容。

附魔与腐化另存参考。普通神像计数只使用冻结词库`specialAffixType`为0／5的源词缀；897属于附魔4、腐化为6，两者都不凑普通一项／两项。物品可以带附魔或腐化，不要求物品总词缀数为2。来源池有三项目标时，仍只生成一条“整个池至少两项”，不枚举配对。

附魔／腐化参考在对应部位下单独显示为词缀标签。例如攻略835护身符的1085／1086显示在“腐化参考”，945仍是普通目标。05只列普通装备底材，保留原R82普通／魔法／稀有／崇高范围，增加同BD对应部位目标T7条件，不加等级或锻造潜能门槛。裸底材、非目标T7、T8均不能通过05；另一BD的词缀不能配这个BD的底材。如果未填对应部位目标，预览会说明未生成该05规则。暗金用01，祭坛与神像底材各在03／04。数量来自当前BD来源，没有5项限制。

底材的一项层／两项层范围保留来源差异。内置Flay示例两层均收Weaver／Lagon，这是之前明确审阅的定制；再次导入原Strict会先保留它自己的底材范围，可在界面修改。

## 练级接口

每个BD的`profiles.endgame`与`profiles.leveling`互不自动复制。练级只填写一份装备词缀池和一份底材列表，不需要逐部位分配词缀，不再填写R编号。词缀按同一个BD计分，单个ID不重复计数；不同BD不能合计。程序从冻结词库的装备类型范围判断哪些部位只有一个可出现目标。

| 通道 | 门槛与退出点 |
|---|---|
| 练级品质 | 0–29级至少一项目标；30–49级目标阶数合计≥5；50–79级合计≥8；80级退出。 |
| 单可用目标例外 | 该装备类型在该BD池中只有一个可出现目标时，50–79级单目标T≥5即可。池里有多个可出现目标而当前物品只掉一项，不属于这个例外。 |
| 练级底材 | 0–29级允许指定裸底材；30–59级指定底材＋同BD至少一项目标，阶数不限；60级退出。 |
| 普通练级拆解 | 只使用填写的BD目标，沿用原T≥3拆解门槛，0–49级；50级退出。 |
| 原职业／泛用拆解 | 原R84–90名单与T4／T5门槛保留，原常驻通道改为0–59级，60级退出；职业通道按目标关联启用。 |
| 初期兜底 | 原0–9级全物品保留；删除10–29级所有稀有、未指定早期底材及武器示例通道。早期崇高原池仍在60级退出。 |

例如60级T5＋T3同BD目标可通过品质层，T3＋T2不能；两个BD各自T4不能合计8。独立底材／拆解／通用保护通道在各自退出前仍可能保留品质不达标的物品。终局目标规则全程参与，80级只退出普通装备练级层。

Raxx通用神像与腐化保留为独立规则，不掺入BD目标。R128／129仅使用原普通49项，保留原90／75退出点；R135保留其普通池中属于这些共通目标、或词库class为0／1的条目，删去职业技能专属示例，仍60退出。附魔4／腐化6不凑普通神像数。R75腐化18项均class=0，保留原60退出点；不会因为BD参考腐化而另行放宽。BD神像一项／两项规则常驻、先于通用层，主粉副蓝。

JSON接口示例（对应BD的`profiles.leveling`）：

```json
{
  "affixes": [26, 945, 98, 643, 502, 45, 28, 27],
  "bases": [{"type": "RING", "bases": [7]}, {"type": "RELIC", "bases": [15, 18]}]
}
```

练级为空时不猜目标、不沿用Raxx武器／底材示例。导入旧配置会把旧装备目标和已启用的装备R入口合并为两份列表，原始练级配置保存在`legacy_leveling`，随整套配置备份，不能把旧神像／暗金等无声挪入普通装备池。

## 合并与导出

左侧勾选决定本次收集范围。主套路粉色，副套路蓝色，同条件共享按主处理；通用高价值层使用通用档位提示。所有勾选BD同等收集。取消当前主套路时，会选择仍勾选的一个BD作为主。

“预览规则”显示实际顺序、声音、部位、目标和门槛，可过滤查看。终局／练级切换只切换编辑内容；“导出filter”始终生成一份包含两阶段的`LE-filter.xml`，不因停留在练级页而丢掉终局目标。成品删除原蓝色说明文字；原始资料、基底模板和历史v3快照保留。

| 档位 | 当前内容 |
|---|---|
| 彗星 | 任意至少三条恰好T7、任意LP≥3、任意WW≥20。 |
| 灵感 | 两条BD目标T7；双T7中至少一条对应部位BD目标T7；神像两普通目标；BD1LP、任意2LP；Raxx名单及BD目标WW17–19；一般传奇。 |
| 开始 | BD目标单T7；其余任意双T7；神像一普通目标；非BD1LP；Raxx名单及BD目标WW14–16；祭坛一项目标。 |
| 铁匠 | BD0LP／低WW；Raxx珍贵暗金／套装名单；非目标单T7＋对应部位低阶BD目标；原崇高实验规则；T8兜底。 |
| 静音 | 额外单T7阶段储备、练级品质／底材、终局05、普通拆解和其余Raxx静音层。没有地图图标或光柱；BD规则主粉副蓝，通用规则沿用原色。 |

T7计数是恰好7阶；T8不参与双／三T7，也不冒充BD目标T7。T8本身最多铁匠，其余词缀成立更高档条件时按那些条件提示。额外单T7阶段默认保留，在界面手动关闭；没有专门T6规则，T6可按普通目标评分参与练级。

超过游戏200条规则时明确报错，不截断；减少勾选BD或重复分组后再导出。未知ID会提示，生成时不能假定其词缀类别。

## 数据与验证边界

离线词库来自本项目已核对的Last Epoch Tools `version150`快照：1156词缀、489暗金／套装条目、918底材条目；其中包含旧／隐藏内容，不表示全部仍可掉落。源地址与哈希在[sources/tool-catalog.json](../sources/tool-catalog.json)，更新版本时需重新核对词库。运行与生成不需要`.cache`或外网。

已用两份Strict及骷髅Very Strict核对提取；自动测试覆盖T7优先级、T8、普通神像计数、LP／WW、主副共享、阶段开关、分段评分／单候选例外、05、50／60／80退出、跨BD隔离、旧配置迁移、200条上限、确定性与XML结构。有限匹配测试不等于游戏客户端实测；客户端导入及声音播放仍需在游戏中验证。

开发验证命令：

```powershell
python -X utf8 -m unittest discover -s tool -v
```
